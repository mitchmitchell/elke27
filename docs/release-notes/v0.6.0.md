## What's Changed

0.6.0 is a minor release (2026-11-17) with new public API: area entry/exit delay
state, arm night via Stay Instant, firmware capability fields, and stricter
snapshot publication after area and zone status reads. Read **Upgrade notes**
before upgrading integrations that arm at night or read area/zone status.

### New API

- **`AreaState.delay_state` and `DelayState` (#141).** Each area exposes
  `delay_state` as `DelayStateNone`, `DelayStateEntry`, or `DelayStateExit`.
  `AreaState.entry_delay` is true during entry delay; `AreaState.arming` is true
  during exit delay (derived from `delay_state`). Remaining seconds follow the
  panel's five-second status broadcasts only. Entry delay is simulator-proven
  only; hardware entry behavior is not claimed in this release.
- **`PanelInfo.application_firmware` and `AreaState.night_arm_supported`
  (#140, #142).** Application firmware from `control.get_version_info` and a
  per-area night-arm capability flag are on the public snapshot.
- **Exported delay types:** `DelayState`, `DelayStateNone`, `DelayStateEntry`,
  `DelayStateExit` (#141).
- **Arm night errors (#140, #142):** `Elke27PanelApplicationFirmwareUnknownError`,
  `Elke27NightArmFirmwareTooOldError`, `Elke27StayInstantRequiredError`.
  Firmware below the minimum raises `Elke27NightArmFirmwareTooOldError` with the
  message "Arm night requires panel application firmware 0.0.5.37 or later."
- **Status publication (#144):** `Elke27SnapshotPublicationError` when snapshot
  replace fails during reply publication.

### Behavior

- **Arm night maps to Stay Instant (#140, #142).** `async_arm_area` with
  `ArmMode.ARMED_NIGHT` sends `area.set_arm_state` with `ARMED_STAY_INST`.
  Panel status `ARMED_STAY_INST` maps to `ArmMode.ARMED_NIGHT`.
- **Exit/entry delay reconciliation (#141).** Partial `area.get_status` payloads
  no longer clear `ee_timer` / `alarm_zone` on unrelated updates; exit-delay
  semantics follow documented fields and five-second ticks.
- **Status reads wait for snapshot publication (#144).** (a) Direct
  `area_get_status`, `zone_get_status`, and `zone_get_all_zones_status`, and arm
  or bypass writes whose reply includes confirmed status, wait for publication on
  that command. (b) Ack-only arm or bypass runs a follow-up status read; failures
  of that nested read (including publication wait) return `ok=True` with
  `status_refresh_ok=False` on the write; only `async_arm_area` with
  `ArmMode.ARMED_NIGHT` raises `Elke27CommandOutcomeUnknownError` on that
  refresh-failed path (Away/Stay arm, disarm, and bypass return without raising).

### Upgrade notes

#### Arm night (Stay Instant)

- `ArmMode.ARMED_NIGHT` now sends `area.set_arm_state` with
  `arm_state=ARMED_STAY_INST` (Stay Instant), not a separate night wire mode.
  The panel must run application firmware **0.0.5.37 or later** (the `app` field
  from `control.get_version_info`, not SSP).
- Before the command is sent, if application firmware is not yet known,
  `async_arm_area(..., mode=ArmMode.ARMED_NIGHT)` raises
  `Elke27PanelApplicationFirmwareUnknownError` (subclass of `Elke27InvalidArgument`).
- If firmware is known and below 0.0.5.37,
  `Elke27NightArmFirmwareTooOldError` (subclass of `Elke27InvalidArgument`) is
  raised with `required` and `actual` version tuples and the message
  "Arm night requires panel application firmware 0.0.5.37 or later."
- A panel refusal on the arm command still raises `Elke27PanelError` (subclass
  of `Elke27ProtocolError`) with `panel_error_code` and `reason`.
- If the panel accepts the write but Stay Instant did not take effect,
  `Elke27StayInstantRequiredError` (subclass of `Elke27Error`) is raised.
- If the panel accepts the write but `async_execute` returns `status_refresh_ok=False`
  after the follow-up read, or the area is missing from the snapshot after refresh
  (#142), `async_arm_area` with `ArmMode.ARMED_NIGHT` raises
  `Elke27CommandOutcomeUnknownError` (subclass of `Elke27TimeoutError`) with
  `route=("area", "set_arm_state")`. The underlying `async_execute` result remains
  `ok=True` in the refresh-failed case. Away and Stay arms with
  `status_refresh_ok=False` return without raising, like disarm and bypass.
- Write helpers also raise `Elke27CommandOutcomeUnknownError` when `async_execute`
  returns `ok=False` after a confirmed send with no reply (same as earlier releases).

#### New and related error classes

| Class | Subclasses |
| --- | --- |
| `Elke27PanelApplicationFirmwareUnknownError` | `Elke27InvalidArgument` (`ValueError`) |
| `Elke27NightArmFirmwareTooOldError` | `Elke27InvalidArgument` (`ValueError`) |
| `Elke27StayInstantRequiredError` | `Elke27Error` |
| `Elke27SnapshotPublicationError` | `Elke27ProtocolError` → `Elke27Error` |
| `Elke27PanelError` (arm rejections) | `Elke27ProtocolError` → `Elke27Error` |
| `Elke27CommandOutcomeUnknownError` (ARMED_NIGHT: failed refresh or area missing after refresh; also no-reply on write helpers) | `Elke27TimeoutError` → `Elke27TransientError` → `Elke27Error` |
| `Elke27DisconnectedError` (publication wait failure) | `Elke27TransientError` → `Elke27Error` |

#### Area and zone status reads

**(a) Direct reads and confirmed-status arm/bypass replies**

- After a successful reply for `area_get_status`, `zone_get_status`, or
  `zone_get_all_zones_status`, or for `area_set_arm_state` / `zone_set_status`
  when the reply already includes confirmed status, `async_execute` waits until
  kernel dispatch publishes the status into `get_snapshot()`. The wait is bounded
  by the command deadline: the per-attempt request timeout
  (`ClientConfig.request_timeout_s`, 5 s by default, or the call's `timeout_s`)
  times the number of transport attempts (3 by default), plus the backoff between
  attempts (0.5 s + 1 s by default), counted from just before the command is sent,
  which is 16.5 s with the defaults. A follow-up status read and the publication
  wait only get what is left of it.
- If the deadline passes before dispatch completes, the command still returns
  `Result(ok=True, ...)` with the panel JSON payload; a WARNING is logged.
  `get_snapshot()` may still show stale state until publication catches up.
  Changed after 0.6.0 (#147): this now returns `Result(ok=False,
  error=Elke27SnapshotPublicationError)` with the message "Timed out waiting for
  snapshot publication."
  Use `Elke27Client.subscribe()` (or `events()`) for `Elke27Event` callbacks with
  `event_type` `EventType.AREA` or `EventType.ZONE`, or run another status read
  later.
- If the link drops while the command is waiting for the panel reply,
  `async_execute` returns `Result(ok=False, error=Elke27DisconnectedError)` with
  message "Connection lost during the command."
- If the link drops after the reply arrived but before snapshot publication on that
  same command finishes, `async_execute` returns `Result(ok=False,
  error=Elke27DisconnectedError)` with message "Connection lost while waiting for
  snapshot publication."
- If rebuilding the snapshot during that publication fails, `async_execute`
  returns `Result(ok=False, error=Elke27SnapshotPublicationError)` (subclass of
  `Elke27ProtocolError`). These `ok=False` results are not raised from
  `async_execute`; public typed helpers raise when the outer `async_execute`
  returns `ok=False` (including `Elke27CommandOutcomeUnknownError` when the frame
  was sent but no reply arrived).

**(b) Ack-only arm or bypass writes**

- When the write reply has no confirmed status, the client runs a follow-up
  `area_get_status` or `zone_get_status` (nested `async_execute`). Publication
  wait applies to that nested read, not to the outer write command.
- Any failure of the follow-up read (transport, timeout, or a failed publication
  wait on the nested `async_execute`) is treated as a failed refresh: the write
  returns `Result(ok=True, status_refresh_ok=False)`, logs a WARNING, and marks
  the area or zone stale. The outer write does not return `ok=False` for
  `Elke27DisconnectedError` or `Elke27SnapshotPublicationError` from the nested
  read. On that refresh-failed path, only `async_arm_area` with `ArmMode.ARMED_NIGHT`
  raises `Elke27CommandOutcomeUnknownError` (failed follow-up or area missing after
  refresh); `async_arm_area` with Away or Stay, `async_disarm_area`, and
  `async_set_zone_bypass` return without raising (`CommandResult.status_refresh_ok`
  when `return_result=True`). A no-reply `async_execute` on any write still
  surfaces `Elke27CommandOutcomeUnknownError` through helpers via `ok=False`, not
  via `status_refresh_ok`.
