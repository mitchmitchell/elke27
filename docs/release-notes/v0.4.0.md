## What's Changed

0.4.0 is a minor release because it removes a public field and changes how
vacation arming is reported. Read **Breaking changes** before upgrading.

### Breaking changes

- **`AreaState.trouble` is removed (#102).** Use `AreaState.trouble_status`,
  which holds the documented `troubles` string from `area.get_status`.
- **Vacation now counts as armed (#100).** `ARMED_VACATION` maps to the new
  `ArmMode.ARMED_VACATION`. It used to map to `None`, which Home Assistant
  showed as disarmed.

### Bug Fixes

- **Triggered alarms are reported (#98).** `AreaState.alarm_active` is now set
  from the `alarms` and `alrm_snd` fields of `area.get_status`, so an armed area
  in alarm shows as triggered. `FIRE TROUBLE` and `CO TROUBLE` don't count as
  alarms.
- **Exact arm-state matching (#100).** `arm_state` strings are matched exactly.
  `ARMED_STAY_INST` maps to `ARMED_STAY`; `ALARM_MEM` sets the new
  `AreaState.alarm_memory`. Unknown values log one warning and stay `None`.
- **Connection events (#50, #80).** `connect()` no longer misses a disconnect
  that happens during setup, and a failed HELLO that isn't a panel refusal no
  longer emits an unpaired `connected=False`.
- **Keepalive rescue on Python 3.11 (#88).** A probe is rescued only by traffic
  received after its own send time.

### New API

- `Elke27CodeRejectedError` for panel user-code rejections (#76).
- `E27Kernel.keepalive_stats` and the `KeepaliveStats` dataclass (#81).
- `KeepaliveTestHooks` for deterministic keepalive tests (#79).
- `PanelState.barriers` typed as `BarrierStateMap` (#87).

### Docs

- Private reference pointers removed from `PERMISSIONS.md` and `ADR-0107` (#108).
