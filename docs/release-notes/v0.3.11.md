## What's Changed

### Bug Fixes

**A dead panel link is detected within seconds** (#18, #20)

With the network cable pulled, the library took about 2 minutes to notice: every
send, including the unanswered keepalive itself, postponed the next probe, and two
misses were needed. Probes are now scheduled from the last message *received*, the
first unanswered probe disconnects, and the probe timeout is 5 s. Defaults changed:
`keepalive_max_missed` 2 -> 1, `keepalive_timeout_s` 10 -> 5 (interval stays 30 s).

When a command's reply times out and nothing at all arrived from the panel since it
was sent, the library probes immediately. The new `Elke27Client.request_link_check()`
lets callers (e.g. the Home Assistant integration on a command timeout) trigger the
same probe.

**Connection loss is logged once** (#19, #20)

A drop logged `Panel connection lost` twice at ERROR, and a deliberate disable also
logged ERRORs. Now a real loss logs one WARNING, the restore logs INFO, and a
deliberate close logs DEBUG only.

**`async_execute` panel rejections and PIN validation** (#11)

**`async_execute` panel rejections use the public error type**

Commands such as `light_set_status` that failed on the panel with a non-zero
`error_code` returned the internal `E27PanelErrorResponse` on `Result.error`.
`async_execute` now maps those replies to `Elke27PanelError` (with
`panel_error_code`, `reason`, and a warning log), matching `async_arm_area`,
`async_disarm_area`, `async_set_zone_bypass`, and `async_set_output_status`.

**PIN validation accepts ASCII digits only**

String PINs were validated with `str.isdigit()`, which accepts Unicode numerals
(e.g. `²`). Coercion then called `int()` and raised `ValueError` outside the
expected error path. Only non-empty ASCII digit strings (`0`–`9`) are accepted;
anything else raises `Elke27InvalidArgument` before a request is sent.

### Behavior Changes for `async_execute` Callers

- **11008 is a normal panel error.** `async_execute` used to turn a 11008 reply
  into the internal `AuthorizationRequired`. That special case is removed: a 11008
  reply now comes back as `Elke27PanelError` with `panel_error_code == 11008` and
  reason `"not authorized"`. Code that checked for `AuthorizationRequired` on
  `Result.error` should check `Elke27PanelError.panel_error_code` instead.
- **Bad PINs raise `Elke27InvalidArgument`.** `async_execute` callers, including
  `control_authenticate`, now get `Elke27InvalidArgument` instead of the internal
  `InvalidPinError` for a non-ASCII-digit string, zero, a negative number, `bool`,
  or a non-integer type. Nothing is sent to the panel.
