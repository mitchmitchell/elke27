### Bug Fixes

**Quieter logs while the panel is unreachable** (#21, #24)

During an outage, the Home Assistant reconnect loop calls `async_connect` every few seconds,
and each failed attempt logged `Connect failed (attempt n/2)` at ERROR. That flooded the log,
even though `Panel connection lost` already reported the drop once at WARNING. Now:

- After `Panel connection lost`, more transient connect failures log at DEBUG only.
- If the panel was never connected, the first transient failure logs once at WARNING. Later
  ones log at DEBUG.
- Non-transient failures (for example invalid link keys or auth) and unrecognized connect
  errors still log at ERROR with a traceback.
- The first successful connect after logged transient failures logs INFO
  `Panel connection established after connect failures`. A restored link still logs
  `Panel connection restored` at INFO.
- (*) The two-attempt connect loop and the backoff are unchanged. The integration owns
  the backoff.

This replaces the v0.3.11 note that each failed reconnect attempt logs at ERROR.

### Tests

- A first successful connect with no earlier failures does not log the
  "established after connect failures" INFO line (#25).

### Upgrade notes

- (*) No API changes.
- Log filters or alerts that matched `Connect failed (attempt n/2)` at ERROR during outages
  will no longer fire. Watch for `Panel connection lost` (WARNING) instead. For a panel that
  was never connected, also watch for the first `Connect failed` WARNING (logged once; later
  failures are DEBUG).
