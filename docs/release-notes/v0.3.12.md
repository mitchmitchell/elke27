### Breaking / behavior changes for callers

**Commands while disconnected raise `Elke27DisconnectedError`** (#26, fixes #13)

- What changed:
  - A command sent with no session used to raise `Elke27PermissionError`, which looks like a
    panel refusal. It now raises `Elke27DisconnectedError` ("Client is not connected.").
  - A connection lost during a command now raises `Elke27DisconnectedError` ("Connection
    lost during the command."). Before, it raised `Elke27TimeoutError`.
  - Real panel refusals still raise `Elke27PermissionError`.
- What to do: if you catch `Elke27PermissionError` or `Elke27TimeoutError` for these cases,
  catch `Elke27DisconnectedError` and treat it as transient.

**`async_connect` no longer retries auth or link refusals** (#28, fixes #14)

- What changed:
  - Wrong credentials, invalid link keys and other non-transient failures fail on the first
    attempt.
  - Transport-class failures may still be retried once within the call. A transport failure
    that will be retried logs `Connect failed (attempt 1/2)` at DEBUG only.
  - `asyncio.CancelledError` now propagates out of connect instead of being swallowed.
- New connect error mapping:
  - `E27Timeout` → `Elke27TimeoutError` (was `Elke27ProtocolError`).
  - `E27NotReady` → `Elke27ConnectionError`.
  - Wrapped kernel failures now map to `Elke27ConnectionError`, `Elke27TimeoutError`,
    `Elke27AuthError` or `Elke27CryptoError` when the cause matches.
  - A HELLO deadline timeout is retried as transient. A malformed HELLO is still permanent.
- What to do: update `except` clauses that expected `Elke27ProtocolError` from connect. Make
  sure task cancellation around `async_connect` is handled.

### New

**Exit-delay fields on area state** (#32)

- What's new: the area snapshot exposes `arm_cmd_mode`, `ee_timer` and a derived `arming`
  for the arm exit delay. Full rules are in `docs/CHANGES.md` and `CLIENT_CONTRACT.md`.
- Use `arming` only after a full status read. Missing fields never set it.

### Bug Fixes

**Quieter logs while the panel is unreachable** (#21, #24)

- After `Panel connection lost`, more transient connect failures log at DEBUG only.
- If the panel was never connected, the first transient failure logs once at WARNING. Later
  ones log at DEBUG.
- Non-transient failures and unrecognized connect errors still log at ERROR with a
  traceback.
- The first successful connect after logged failures logs INFO `Panel connection established
  after connect failures`. A restored link still logs `Panel connection restored`.
- A test confirms that a first successful connect with no earlier failures doesn't log that
  INFO line (#25).
- This replaces the v0.3.11 note that each failed reconnect attempt logs at ERROR.

**Session I/O hardening and better disconnect diagnostics** (#30, refs #8)

- Changes:
  - Outbound sends are serialized and have a write deadline.
  - Partial sends are logged.
  - A failed outbound send tears the session down.
  - A disconnect is reported once even if two paths detect it.
  - Disconnect logs include `err_msg=`.
- This is defensive. The hardware drop in #8 is **not** confirmed fixed.

**HELLO read timeout restored** (#33) <!-- not in the requested list; merged on main, verify scope -->

- After the short pre-HELLO probe, the socket read timeout goes back to `io_timeout_s`.
- Pre-HELLO greeting bytes now log at DEBUG instead of WARNING.

### Pending (not merged)

  - Arming, zone bypass and output commands are not resent once confirmed sent.

### Upgrade notes

- Review the two breaking changes above if you catch `Elke27PermissionError`,
  `Elke27TimeoutError` or `Elke27ProtocolError`.
- Log filters or alerts that matched `Connect failed (attempt n/2)` at ERROR during outages
  will no longer fire. Watch for `Panel connection lost` (WARNING). For a panel that was
  never connected, also watch for the first `Connect failed` WARNING (logged once; later
  failures are DEBUG).
